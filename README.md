# selfstack

**先把自己摸清楚，再定期去外面找哪些东西值得换进来。**

一个零第三方依赖的命令行工具，回答两个问题：

- 我这套生产体系**到底由什么组成**
- 外面哪些开源项目**值得我升级**，值得到什么程度

---

## 为什么还要写一个

这两个需求本来是分开被解决的，但中间那根线没人接。

| 已有的东西 | 代表项目 | 干到哪一步 | 卡在哪 |
|---|---|---|---|
| 依赖升级机器人 | Renovate、Dependabot、Depfu | 同一个包出新版本就开 PR | 只认包管理器。**不认识你的技能、通道、自动化任务** |
| SBOM / 依赖情报 | Syft、Bomly、OSV-Scanner、cli-tool-audit | 盘点装了什么、有没有 CVE | 只读代码依赖，**不做「值不值得换」的判断** |
| Agent 自我改进 | agent-self-improvement、Hermes 自进化、SICA | 从历史会话总结经验，固化成技能 | **只向内看**。外面出了更好的方案它不知道 |
| Agent 可观测性 | Langfuse、agenttrail、Arize Phoenix | 看 trace、成本、报错 | **事后诊断**，不是事后决策 |

缺的是这条链路闭环。

selfstack 干的就是补上这段：**给自己画一张像，拿这张像去外面筛，筛完按自己的缺口打分排序，最后把结论交给人。**

---

## 它跟 Renovate 到底有什么不同

Renovate 问的是「**这个包有新版本吗**」。

selfstack 问的是「**我这套东西少了哪块能力，外面有没有东西能补上**」。

前者管的是版本号，后者管的是能力。一个 already-have 的项目出了新版属于前者，一个你压根没听说过但正好缺的工具属于后者。两种需求都存在，Renovate 只管第一种，selfstack 主要管第二种，顺带把第一种也带上（`watched_repos` 和 `watched_packages` 那两块）。

## 快速开始

```bash
# 装（零依赖，纯标准库）
pip install -e .

# 1. 生成配置
selfstack init

# 2. 编辑 ~/.selfstack/config.json，把 roots 和 skill_dirs 填上你的目录

# 3. 盘自己（能力清单不用写，它自己归纳）
selfstack inventory

# 4. 一条龙跑完，出报告
selfstack run

# 5. 看报告
selfstack show
```

## 五个阶段

```
inventory ──▶ radar ──▶ evaluate ──▶ report ──▶ （人来决定要不要动）
  我是谁        外面有啥      值不值得       写成给人看的东西
```

### 阶段一 `inventory`，给自己画像

扫的东西包括运行时版本、工作区里的 git 仓库、技能目录、MCP 服务注册、声明要盯的 CLI 工具、凭证目录。

**能力清单是算出来的，不用你手写。** 它把每个技能的名字和 SKILL.md 里的描述当成一篇文档，算 tf-idf，然后每一轮挑一个能把最多部件解释掉的主题词，重复到解释完；超过总量一成二的大簇会在子集上重算再往下拆。真机上跑的结果是自动归纳出飞书协作、企业微信文档、浏览器自动化、表格生成、HTML 文档流水线、PDF、长文写作、公众号发布、金融数据、量化交易、人员检索这些能力面，没人提前告诉过它有这些东西。

版本号目录、资源子目录（scripts / assets 那类）、没有说明书的空目录一律不当部件，不然榜首永远是一串谁也读不懂的哈希。

如果你非要自己指定清单，在配置里写 `capabilities` 就行，写了就听你的。默认不写。

### 阶段二 `radar`，去外面捞

六个来源，覆盖两类升级：

| 源 | 管的是 | 说明 |
|---|---|---|
| GitHub 仓库检索 | 换新 | 只在最近有提交、star 过线的里面挑 |
| GitHub release | 升版本 | 盯你已经在用的仓库有没有发新版 |
| PyPI / npm registry | 升版本 | 手上的包落后了多少 |
| awesome 类清单 | 换新 | 人工筛过的，噪声比纯检索小得多 |
| Hacker News | 热度信号 | 判断是不是真有人在关心 |

GitHub 搜索 API 未认证时一小时只有 60 次额度，工具自己会限流，超了就降级不报错。

### 阶段三 `evaluate`，打分

分数必须能解释，每一项都带明文理由：

| 维度 | 满分 | 在问 |
|---|---|---|
| 契合度 | 40 | 跟我现在这套能力面的重合程度。另外，它主打的方向如果是外面反复出现、而我一堆部件里一个都不沾的，额外加分 |
| 成熟度 | 25 | star 量级、有没有归档 |
| 动量 | 15 | 最近一次提交在多久以前 |
| 成本 | 10 | 反向计。钉死的核心件成本高，纯版本升级成本低 |
| 风险 | 10 | 反向计。传染性许可证、预发布版本直接扣 |

两条防虚高的规则：

- awesome 清单抽出来只有个仓库名，没有 star 和时间信息。不补的话它们全落同一个保底分，**一堆陌生项目会集体挤进榜首把真信号埋掉**。所以默认会给最多 15 条补全 GitHub 元数据（`--enrich` 可调）
- registry 类候选**没配当前版本号就不算数**，契合度直接砍一半。连自己现在用的啥版本都不知道，谈不上「是否落后」

### 阶段四 `report`，写成给人看的

产出 Markdown 报告，每份都包含体系画像、自动归纳的能力面清单、候选排行榜、逐条判断依据、跟上次的 diff、数据源健康度。

**每条建议必须能回答三个问题**：为什么是我、要花多大代价、有什么坑。

### 阶段五 `schedule`，让它自己跑

```bash
selfstack schedule              # 注册每天 9:30 跑一次
selfstack schedule --remove     # 撤掉
```

Windows 走 `schtasks`，Linux / macOS 走 `crontab`。定时任务里跑的还是同一条只读命令。

**如果你的日常入口是个 AI Agent，那就别自己注册系统计划任务了。** 直接让 Agent 定时调 `selfstack run` 再把报告翻译成人话，维护成本更低，出问题也有人第一时间看见。分散在两台机器上的定时任务，失败起来都很安静。

注意 `selfstack schedule` 生成任务时用的是当前解释器的绝对路径加 `-m selfstack.cli`，不是裸 `selfstack`。装进隔离环境的东西压根不在全局 PATH 上，写裸命令等于埋雷。

## 底线

这是整套设计的第一条，也是唯一不可协商的一条。

- **不安装任何东西**。报告里所有建议都是建议，一个包都不装，一行配置都不改
- **不开 PR、不开分支、不碰别人的仓库**
- **不花一分钱**。没有 API 付费调用，没有云服务依赖
- **凭证只读外壳**。碰凭证目录只记文件名和大小，**绝不读内容、绝不打开**
- **要不要动手，人说了算**

工具的输出是一份报告，不是一次执行。这个边界一旦破了，它就不是工具而是一颗定时炸弹。

## 配置要点

配置文件是 JSON，默认 `~/.selfstack/config.json`。用 JSON 不用 YAML 就是为了不加依赖。

最小可用配置长这样，`capabilities` 不写就自动归纳，下面这个写法是给自己指定清单的示例：

```json
{
  "roots": ["~/projects"],
  "capabilities": [
    {
      "id": "browser",
      "name": "浏览器自动化通道",
      "why": "对外获取信息的主腿，断了就只能靠 API",
      "match": ["jev", "playwright", "browser-use"]
    }
  ],
  "queries": [
    { "q": "browser automation llm", "caps": ["browser"], "hn": true }
  ],
  "watched_repos": [
    { "repo": "browser-use/browser-use", "caps": ["browser"], "current_version": "v0.1.0" }
  ]
}
```

完整示例见 `examples/`。

需要代理就设 `"proxy": "http://127.0.0.1:7897"`。想让 GitHub 放宽限流就设 `GITHUB_TOKEN` 环境变量（不设也能跑，只是额度紧）。

## 产出落在哪

```
~/.selfstack/state/
├── inventory-latest.json      体系画像快照
├── candidates-latest.json     本轮候选
├── proposals-latest.json      打分结果
├── report-latest.md           最新报告
├── report-2026-09-25.md       按日期归档
└── snapshot-2026-09-25.json   完整快照，用于回看
```
